Weekly usage is the highest reading of the week, which is the whole week's usage when a reading landed within 6 hours of the reset. A week read earlier than that is marked at least, since anything used after the last reading (a cloud Claude Code session overnight, a phone) isn't in it; only complete weeks set the typical week. Keep a claude.ai tab open in Chrome over the weekly reset to make a week complete. Weekly % per session is how much of the week a full 5-hour session costs, from the two meters' paired rises. Anthropic publishes the session limit as a multiple of Pro's (Max 5x is 5×, Max 20x is 20×) and no figure for the week, so that rate is what converts a week into Pro sessions: the unit both plans share. The comparison is only as good as the weeks are alike — a week of mostly Sonnet costs differently from one of mostly Opus.

Workflows

How much of your weekly usage goes through workflow runs rather than chats you drive yourself — measured the same way as Daily Usage, from the rise in the weekly meter while a run's step was working. Counted only for steps that had Claude to themselves.

Nothing measured yet. This fills in as workflow runs finish steps.

Measured by difference against a browser-wide meter, so a step only counts when it had Claude to itself: every claude.ai tab records the span of each assistant turn, and a step that overlapped a turn in any other conversation — yours, a scheduled send, another run — is left out rather than credited with that work. Steps whose weekly window reset part-way through are left out too, since there is nothing to difference. Both make this a floor: real workflow usage is higher than what's shown here, never lower.

Scheduled Sends

Queue files (and an optional prompt) to a new chat — optionally in a Project — to send at a set time or when your 5-hour usage next resets. Files are stored in the extension until they go out.

No scheduled sends queued.

Heads-up: a job can only fire while your browser is running and you're logged into claude.ai — at fire time the extension opens a background claude.ai tab, attaches the files, types the prompt, and clicks Send. If Claude is down, the job waits and sends itself once the outage clears (up to 6 hours, then it goes anyway); Run now overrides the wait.

Workflows

A workflow runs one piece of work through several chats that hand it back and forth — chat A drafts, chat B criticises, A revises, and so on — so each pass improves on the last. Each workflow is a template: name it for the matter, add that matter's documents, and starting a run hands both to the run and puts the template back to its resting name, empty and ready for the next one.

Runs

No runs yet. Start one from a workflow above — it opens its own Chrome window, walks the steps, and waits for each reply before sending the next.

A run drives the real UI, so it needs your browser open and logged into claude.ai, and it leaves each chat's conversation open so you can read it. Claude's reply travels between chats the way you would move it: the copy box under the finished answer, which copies the answer without the thinking. If Claude is down, the run waits mid-workflow and picks up where it left off.

Incognito recovery

claude.ai doesn't save an incognito chat — that's the point of one — so closing the tab takes the work with it. While an incognito chat is open the extension keeps a running copy here, against exactly that accident. Kept for three days, then deleted: a permanent record of a conversation you asked not to be recorded isn't a recovery feature.
